## ⛔ 驗收方式只有一種，沒有例外

**開瀏覽器、用 Playwright 一個字一個字打進輸入框、按 Enter、看畫面上回什麼。**

- **禁止**用 `requests`／`curl`／`page.request` 當通過的證據
- **禁止**只看 `evidence` 的 tool 名稱就說通過 —— **要看畫面上顯示給人的那句話，而且語意要對**
- 一律 `pressSequentially()` 逐字打進 `getByRole('textbox', { name: '輸入訊息' })`，再 `press('Enter')`
- 每一句截圖存 `docs/screenshots/`，檔名對應測項編號
- 回報要附**畫面上實際出現的文字**，不是 API 的 JSON
- **跑腳本不要截尾**，用 `Tee-Object` 留完整 log

**理由**：先前有三輪用 API 測「通過」，但使用者在畫面上打同一句話得到的是罐頭訊息或原始 JSON。
**API 通過不等於畫面通過，只有畫面上的字算數。**

## 【1】重產資料 —— 這是所有東西的地基

### 現在的問題（我量過，數字是真的）

```
demo-50-tight.xlsx
  50 張訂單  →  只落在 32 個不同座標上
  25.09335, 121.52532   3 張
  25.06265, 121.51269   3 張
  25.05535, 121.60731   3 張
  25.06865, 121.58768   3 張
  （另有 10 個座標各 2 張）
  最近鄰距離中位數 = 0 公尺
  50 張裡有 45 張，最近的鄰居在 300 公尺內
```

**一半以上的訂單座標跟另一張完全一樣。** 地圖上只有 32 個點，
所以看起來像兩個點在來回跑。

### 要做

重產 `demo-50-tight.xlsx` 與 `demo-50-relaxed.xlsx`：

| 項目 | 要求 |
|---|---|
| 座標 | **50 張 = 50 個不同座標，一個都不准重複** |
| 分散度 | **最近鄰距離中位數 ≥ 800 公尺**，且**沒有任何一對小於 300 公尺** |
| 涵蓋 | 台北市 12 區 ＋ 新北市 8 區，**每區 2～3 張**，點要落在該區內部不同位置 |
| 地點名稱 | 跟著換成該區看得懂的虛構名稱 |
| 訂單編號 | **維持 ORD-001 ～ ORD-050 不變** |

### 不能破的四條

1. `demo-50-tight` 維持 **49/50**，保留一張排不進去的單，
   而且系統要能講出**是哪一個限制擋住它**（時段／載重／責任區）
2. **VEH-002 身上要有 3 張超過 20 kg 的單**（第 2 幕要用）
3. `demo-50-relaxed` 維持 **50/50**
4. 責任區維持地理連續＋互有備援（現況已經是），**總里程不得回升超過 280 km**

### 連帶要改的

重產會讓寫死座標／地點／區域的地方失效。**只准改那些「事實值」，不准改判定標準**：

```
docs/demo-script.md
docs/demo-qa-matrix.md
docs/demo-scenario-v3.md          ← 把示意數字換成真實數字
frontend/tests/e2e/*.spec.ts       ← 寫死座標或訂單所屬區域的地方
tests/*.py                         ← 同上
```

### 驗收

貼出重產後的實測：

```
不同座標數 = 50
最近鄰距離：最小 ___ m、中位數 ___ m
tight 49/50、總里程 ___ km
relaxed 50/50、總里程 ___ km
VEH-002 超過 20 kg 的單 = 3 張
```

## 【5】訂單看板（取代現在的表格）

### 長這樣

```
┌─ VEH-001 ──┐ ┌─ VEH-002 ──┐ ┌─ VEH-003 ──┐ ┌─ VEH-004 ──┐
│ 1  ORD-014 │ │ 1  ORD-003 │ │ 1  ORD-021 │ │ 1  ORD-008 │
│ 2  ORD-027 │ │ 2  ORD-011 │ │ 2  ORD-033 │ │ 2  ORD-019 │
│      ⋮     │ │      ⋮     │ │      ⋮     │ │      ⋮     │
│ 14 張       │ │ 12 張       │ │ 13 張       │ │ 11 張       │
│ 67.7/120kg │ │ 58.3/100kg │ │ 102/160kg  │ │ 90.4/110kg │
└────────────┘ └────────────┘ └────────────┘ └────────────┘

        [ 上一步 ]  [ 下一步 ]            [ 套用變更 ]
```

### 規則

1. 每欄只顯示 **站次 + 訂單編號**
2. **點一下訂單才展開**：配送時段、重量、預估到達、推薦理由
3. **上車前（PRE_LOAD）**：可跨欄拖（換車）、可同欄拖（換順序）、可刪除
4. **上車後（LOADED）**：只能同欄拖；**跨欄要彈回原位**並顯示物理理由
5. **已發車（DISPATCHED）**：已送達的站不能拖，顯示為灰色
6. 放開後**先試算再套用**，畫面顯示可不可以與代價
7. 不行要說原因：超重、跨出責任區、時段來不及、**違反司機規則**、已送達
8. **上一步 / 下一步**（undo / redo），至少 10 步
9. **數字一律由後端算**，不准前端自己算一套；沿用既有的
   `POST /api/v1/plans/{plan_id}/route-order/preview`，跨車移動需要新端點
10. 鍵盤要能操作（可 Tab 聚焦、Enter 展開）

### 可以換的時候

```
✅ 可以換

  ORD-042  VEH-003 第 3 站  →  VEH-004 第 5 站
  VEH-003  102 → 94.5 kg    路程 -5.2 km    最後一站早 14 分鐘
  VEH-004  90.4 → 97.9 kg   路程 +6.8 km    最後一站晚 18 分鐘
  沒有訂單掉出配送時段

                        [ 套用 ]   [ 取消 ]
```

### 不能換的時候

```
❌ 不能換

  ORD-021 是 38 kg，超過你剛才設的「VEH-002 單件 ≤ 20 kg」。

                        [ 知道了 ]
```
