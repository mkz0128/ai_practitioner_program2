# 平板 Demo 操作指南（線上版）

```
https://ai-dispatch-control-tower.onrender.com/
```

**不用密碼，直接開。** 2026-09-14 21:xx 實測通過。

---

## 開始之前（很重要）

**提早 5 分鐘自己先打開一次。** 免費方案閒置會休眠，第一次開要等大約 50 秒。
等到畫面出現「已完成 49／50 張訂單的排班」才算醒了。

線上版每則訊息大約要 **15～20 秒**（比本機慢，因為是免費機器）。
**等待時不要一直點，畫面上會顯示「理解你的需求…」「呼叫工具計算…」。**

---

## 開場：畫面自己就會排好

不用上傳任何東西，一打開就是：

```
50 張訂單   4 台車   49/50 已安排
```

**第一句話就講這個：**

> 「50 張訂單、4 台車，它自己排完了。**注意是 49/50 —— 有一張排不進去，它沒有硬塞，也沒有偷偷丟掉。**」

### 點一台車（用手指點地圖上方的 VEH-003）

站序數字 1、2、3… 會直接畫在地圖上，其他三台會淡掉。

> 「這台車今天怎麼跑，第一站到第十五站，一眼看得到。」

---

## 第 2 幕：講一句話，它就記住了（**最強的一段**）

打：

```
三號車的老王最近腰傷，比較重的單先不要給他
```

它會回：

```
了解。要限制 VEH-003 的單件重量上限，多重算重？
VEH-003 目前狀況：最大單件 45 kg；超過 20 kg 的有 4 張；超過 25 kg 的有 1 張。
另外請告訴我規則期限：永久、本週或今天。
```

> 「**它沒有自己猜一個數字。** 它反問，而且把現況攤給我看。
> 因為『比較重』這三個字，只有調度員知道是多重。」

接著打：

```
20 公斤以上就不要，永久
```

會出現試算結果與「套用」按鈕。按下去。

> 「這句話被記住了。明天、下禮拜，系統都還記得老王不能搬重的。
> **配送中心最值錢的資產，是老調度員腦子裡那本沒人寫下來的規則書。**」

---

## 第 3 幕：臨時插單

打：

```
客戶剛剛打電話來，有一張急單要今天早上送到，15公斤
```

它會一次列出缺什麼。接著打（**座標要照這個打，這是兩台車的交界**）：

```
ORD-101，大安信義交界示範配送點 Z3-51，臺北市，行政區信義，25.040，121.560，Z3，1 件
```

出現訂單摘要後，打：

```
產生插單預覽
```

**會出現三張方案卡**（2026-09-15 線上實測）：

```
方案 A  VEH-004 第 11 站    +6.3 km   +13.2 分   換車 0      預估 11:34
方案 B  VEH-002 第 1 站     +12.9 km  +26.9 分   換車 0      預估 09:21
方案 C  重排 VEH-004 順序   +11.2 km  +23.4 分   改序 3 張   預估 09:21
```

> 「**這才是重點。它不是幫我決定，是給我三個帶價碼的選擇。**
>
> A 最省，只多跑 6.3 公里，但送得最晚，要等到 11:34。
> B 準時，早上 9:21 就到，但要多跑一倍的路。
> C 一樣早，比 B 省，代價是動到 3 張既有訂單的順序。
>
> **這三個哪個對？看今天油錢重要還是客戶重要。那是調度員的判斷，不是 AI 的。**」

選一張按下去，下面的訂單數會從 49 變 50。

---

## 第 4 幕：同一句話，晚二十分鐘就不行了（**對比很強**）

按右上角「**開始裝車**」。狀態會從「上車前」變「上車後」。

打：

```
這單改派給三號車
```

它會拒絕，並說明是裝車的物理限制。

> 「七點十分可以改，七點半就不行了。不是系統刁難，**是貨已經堆進車裡了。**
> 傳統系統只有一顆重新排班按鈕，按下去會把裝好的車全部打亂。」

---

## 第 5 幕：司機請假

打：

```
三號車今天不能出車
```

會回：

```
VEH-003 今天停駛試算完成：目前可安排 49 張，未安排 1 張。
主要衝突：南區 1 張受時段或路線限制。
可由人工處理：改派備援車、放寬責任區或保留未安排訂單人工處理。
```

> 「它不只說做不到，**它告訴你是哪一區、幾張、還有你可以怎麼處理。**」

---

## 第 6 幕：它會推翻自己（**收尾大招**）

按「**模擬出發**」，把時間軸拉到中間，然後打：

```
今天調度狀況如何
```

它會講出哪台車慢幾分鐘、哪一區停留比較久，並建議調整參數。

> 「早上那個方案是建立在『每站停 3 分鐘』這個假設上的。
> 那個數字是系統上線那天有人隨口填的，然後十年不會變。
> **我們的系統會自己修正，所以它排的班，明天會比今天準。**」

---

## 有人想找碴的時候

打：

```
把所有單重新分配一遍
```

回：「這個我不能改；目前只支援方案卡列出的六種配送調整。」

> 「我們用 8 種說法、3 種對話脈絡測過 24 次，每次都擋下來。
> 你可以自己想一句沒出現過的說法試試看。」

---

## 出狀況怎麼辦

| 狀況 | 怎麼辦 |
|---|---|
| 畫面一直轉、超過 60 秒 | 重新整理頁面，資料會自己重排 |
| 想從頭來一次 | 按右上角「重新開始」，規則和參數都會清乾淨 |
| 回答很慢 | 正常，線上免費機器一則要 15～20 秒。繼續講你的台詞 |
| 有人問路線為什麼是直線 | 「底圖和點位都是真的，只有站點之間的連線是示意直線。接 Google 就會變真實道路，那是設定問題不是架構問題。」 |
| 有人問資料是不是假的 | 「對，全部是我們產生的虛構資料，題目明訂不能用真實客戶資訊。**但座標是真的台北新北位置**，所以距離計算有意義。」 |
