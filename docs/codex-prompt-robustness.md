# 給 Codex 的 Prompt（多樣本、多情境健壯度驗證）

複製分隔線之間整段。

---

## ⛔ 驗證方式只有一種

**全部開瀏覽器、用鍵盤把字打進輸入框、按送出、看畫面上回什麼。**

- **禁止**用 `requests`／`curl`／`page.request` 當通過的證據
- **禁止**只看 `evidence` 的 `tool` 名稱就說通過，**要看畫面上顯示給人的那句話**
- 一律 `pressSequentially()` 逐字打進 `getByRole('textbox', { name: '輸入訊息' })`，再 `press('Enter')`
- 每一格截圖，存 `docs/screenshots/`，檔名對應本文件的測項編號
- **跑任何腳本都不要截尾輸出**，用 `Tee-Object` 留完整 log

---

## 這一輪要做什麼

前面幾輪功能已經做完並驗過。**這一輪不加功能，只做一件事：證明它換資料、換說法、換操作順序都不會壞。**

現在的覆蓋率是這樣，缺口在最後兩欄：

| 測什麼 | 現有覆蓋 | 缺 |
|---|---|---|
| 語意路由 | 3 份 workbook × 8 說法 × 2 次 | 說法數不夠 |
| 越權拒絕 | 1 份 × 8 說法 × 3 脈絡 | 只有 1 份資料 |
| 整場 demo 走查 | **只有 `demo-50-tight` 一份** | **其他樣本沒走過** |
| 連續操作不重整 | **幾乎沒測** | **這是最脆弱的地方** |

**已知最脆弱的一點**（寫在 `docs/demo-qa-playbook.md` Q-09）：
預覽驗證失敗之後，下一則訊息會被誤判成別的流程（「行政區是信義」被當成車輛名稱）。
**這一輪要把這類問題全部挖出來。**

# R1　整場流程換資料重跑

新增 `frontend/tests/e2e/robustness-datasets.spec.ts`。

把 `demo-walkthrough.spec.ts` 的流程抽成可重用函式，然後用下面三份資料各跑一次：

| 樣本 | 預期 |
|---|---|
| `demo-50-tight.xlsx` | 49/50，`ORD-050` 排不進去 |
| `demo-50-relaxed.xlsx` | 50/50 |
| `demo-delivery-40-orders.xlsx` | 依該檔實際結果 |

**重點：斷言要寫成「不論哪一份都必須成立」的那種，不要寫死數字。**

每一份都必須滿足：

1. 匯入後畫面出現「已完成 N／M 張訂單的排班」
2. `你是誰` 回看得懂的中文，**不是 JSON、不是「已完成確定性工具計算」**
3. `三號車的老王最近腰傷，比較重的單先不要給他`
   → 點名 VEH-003、附上**該份資料實際的**重量現況、問上限也問期限
4. 急單流程走得完並產生 **≥2 張實質不同的卡**
5. `把所有單重新分配一遍` → 「這個我不能改」
6. **全程畫面上不得出現** `已完成確定性工具計算`、`{"`、`undefined`、`NaN`、`null`

⚠️ **`demo-50-relaxed` 的 VEH-003 沒有超過 20 kg 的單**，所以第 3 點在 relaxed 上
只要求「有講出該份資料的真實現況」，不要求張數大於 0。
**不要為了讓 relaxed 過而放寬 tight 的標準。**

# R2　同一句話的多種說法

新增 `frontend/tests/e2e/robustness-paraphrase.spec.ts`。

每一組的每一句都要走到**同一個結果**。**禁止 regex／關鍵字比對**，
所以這一題是測模型有沒有真的在判斷語意。

## R2-1 司機限制（都要走司機規則反問流程）

```
三號車的老王最近腰傷，比較重的單先不要給他
VEH-003 的司機身體不好，重的東西他搬不動
三號車那個師傅最近不能搬重物
老王的車不要再放重的貨了
麻煩三號車以後輕一點的貨再給他
```

## R2-2 車輛停駛（都要排除該車並重算）

```
三號車今天不能出車
VEH-003 今天請假
三號車今天壞掉了
三號車今天不跑
三號車今天先不要派
```

## R2-3 越權要求（都要回「這個我不能改」）

```
把所有單重新分配一遍
全部重排一次
今天的單我想整個重新分過
整批重新洗牌
所有單子重新配一次車
redistribute all orders
```

## R2-4 常識問句（都要回看得懂的能力說明）

```
你是誰
你可以做什麼
這個系統是做什麼的
你會什麼
急單需要哪些欄位
載重是怎麼算的
```

**判定**：同一組裡每一句的結果必須一致。
有任何一句跑到別的工具或回罐頭，就是失敗，**記下是哪一句**。

# R3　連續操作不重整（最重要的一塊）

新增 `frontend/tests/e2e/robustness-sequence.spec.ts`。

**整段只開一次頁面，中途不得 reload、不得按重新開始。**

## R3-1 交錯操作

```
1  三號車的老王最近腰傷，比較重的單先不要給他
2  20 公斤以上就不要，永久
3  （按套用）
4  客戶剛剛打電話來，有一張急單要今天早上送到，15公斤
5  ORD-101，信義示範配送點，臺北市，行政區信義，25.033，121.565，Z3，1 件
6  產生插單預覽
7  用 A，但這單先送

10 三號車今天不能出車
11 把所有單重新分配一遍
```

**每一步都要檢查：這一步的回覆是在回這一步的問題，不是在回前面某一步。**
特別是第 8、9 步（查詢類）夾在流程中間，不得被當成還在補急單欄位。

## R3-2 中途放棄再重來

```
1  客戶剛剛打電話來，有一張急單要今天早上送到，15公斤
2  算了不要了
3  哪台車載重最高
4  再加一張急單，內湖，8公斤
```

第 3 步必須正常查詢，第 4 步必須是**全新的**急單流程，不得沿用第 1 步的殘留。

## R3-3 補欄位補到一半插別的話

```
1  客戶剛剛打電話來，有一張急單要今天早上送到，15公斤
2  行政區是信義
3  這樣會不會超載
4  ORD-101，信義示範配送點，臺北市，25.033，121.565，Z3，1 件
```

**第 2 步的「行政區是信義」不得被當成車輛名稱或訂單編號**（這是已知缺陷 Q-09）。
第 3 步必須是查詢，不得吃掉急單草稿。
第 4 步必須能接著把草稿補完。
