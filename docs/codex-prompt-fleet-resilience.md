## 問題

`三號車今天不能出車` 是 demo 一定會被問的題目（`docs/demo-qa-playbook.md` B-1），
而且第 2 幕「老王腰傷」講的就是三號車，評審很可能接著問「那老王請假呢」。

現在的回答是：

```
VEH-003 今天停駛後，目前排不出合法方案；沒有任何訂單能在目前限制下指派。
```

實測四台車：

```
三號車停駛 → 0 張可指派
四號車停駛 → 0 張可指派
二號車停駛 → 49 張可安排，1 張未安排   ← 只有這台是正常的
```

## 兩個原因疊在一起

**① 責任區互不重疊，少一台車就有一整區沒人送**

```
VEH-003 = Z2        VEH-004 = Z1
VEH-002 = Z3        VEH-001 = Z4, Z5
```

**② 更根本的：車隊容量根本不夠**

```
demo-50-tight    總載重 375.4 kg / 總容量 490 kg = 77%
  拿掉 VEH-003（160 kg）→ 剩 330 kg，差 45.4 kg
  拿掉 VEH-001（120 kg）→ 剩 370 kg，差  5.4 kg

demo-50-relaxed  總載重 338.0 kg / 總容量 490 kg = 69%
  拿掉 VEH-003（160 kg）→ 剩 330 kg，差  8.0 kg
```

**光改責任區沒有用。** 重量塞不下就是塞不下，怎麼分區都一樣。

---

# 要做三件事

## 1　把總載重壓到「少一台車也裝得下」

**目標：兩份資料的總載重都 ≤ 330 kg**（＝拿掉最大那台 160 kg 之後的剩餘容量），
最好留一點餘裕，抓 **≤ 315 kg**。

tight 現在 375.4 kg，要減約 60 kg。做法是**把數量多的小單調輕**，不要動重單。

### 不能破的四條

1. **`demo-50-tight.xlsx` 維持 49/50**，`ORD-050` 仍然排不進去。
2. **VEH-003 身上仍要有至少 3 張超過 20 kg 的單**（現在是 45／22／22／22）。
   沒有這個，第 2 幕「20 公斤以上不要給他」會變成「影響 0 張」，整幕是空的。
   驗收閘門 `demo-walkthrough.spec.ts` 有這條斷言。
3. **`demo-50-relaxed.xlsx` 維持 50/50**，總載重同樣壓到 ≤ 315 kg。
4. **區域劃分維持現在的樣子**（Z1 北／Z2 東／Z3 中／Z4 西／Z5 南，地理連續），
   總里程不得回升到 300 km 以上。目前 tight 235.0 km、relaxed 243.3 km。

## 2　每一區都要有第二台車能跑

現在每區只有一台車，改成每區至少兩台，而且**備援區必須與主責區相鄰**：

| 車 | 上限 | 主責 | 備援 |
|---|---|---|---|
| VEH-003 | 160 kg | `Z2` 東 | `Z1` 北 |
| VEH-004 | 110 kg | `Z1` 北 | `Z2` 東 |
| VEH-002 | 100 kg | `Z3` 中 | `Z4` 西、`Z5` 南 |
| VEH-001 | 120 kg | `Z4` 西、`Z5` 南 | `Z3` 中 |

結果是每一區都有兩台車能服務：

```
Z1 → VEH-004 主、VEH-003 備      Z2 → VEH-003 主、VEH-004 備
Z3 → VEH-002 主、VEH-001 備      Z4 → VEH-001 主、VEH-002 備
Z5 → VEH-001 主、VEH-002 備
```

⚠️ **加了備援區之後要重新確認路線沒有變亂**——求解器本來就偏好近的點，
正常情況下不該把車派去備援區。**如果總里程明顯上升，回報數字，不要自己放寬。**

## 3　真的無解的時候，訊息要講清楚

即使做完 1 和 2，還是可能有無解的情況（例如同時停兩台車）。
那時候的訊息現在是：

```
目前排不出合法方案；沒有任何訂單能在目前限制下指派。
```

這不合格。`.agent/skills/daily-dispatch.md` 第 39 行寫得很清楚：

> 導致無解時，指出**是哪條規則與哪些訂單衝突**，提供破例／放寬／取消三個選項。

**要改成**：講出是哪一區、幾張單、為什麼（沒有其他車能服務該區／總容量不足多少公斤），
並附上人工處理的選項。**不准只回一句排不出來。**

# 硬性規則

1. **禁止 regex／關鍵字比對判斷語意。**
2. **不准改任何既有測項的輸入句子或判定標準**，尤其是 `demo-walkthrough.spec.ts`。
3. **不准把前端預設資料改回 relaxed**（`frontend/src/App.tsx` 的 `DEFAULT_DEMO_WORKBOOK`）。
4. **不准在前端用 `requestAnimationFrame` 等畫面重繪。**
   已經因為這個出過兩次事：開場卡在「建立距離矩陣…」、以及**使用者送出的訊息根本沒送出去**
   （分頁沒在繪製時 rAF 不會觸發）。要讓畫面先更新就用 `setTimeout(fn, 0)`。
5. **改完 `src\**\*.py` 一定要重啟 uvicorn**（沒有 `--reload`）。
6. **不要寫 watchdog、不要寫 while 迴圈自動重啟服務。**

# 回報方式

每個區塊給這張表：總格數 / 通過 / 失敗 / 失敗的是哪幾格。
失敗的附上**打了什麼、畫面上實際回什麼、截圖檔名**。

修不好就寫進 `docs/progress.md` 的「待確認」並繼續往下做，不要卡住，也不要動判定標準。

現在開始。先回三句話：你打算怎麼把總載重壓到 315 kg 以下又不動重單、
加了備援區之後里程會不會上升、哪裡不清楚。
