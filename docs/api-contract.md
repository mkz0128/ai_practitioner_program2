# REST API Contract v1

Base path: `/api/v1` except `/health` and `/ready`. Content type is JSON unless the import endpoint specifies multipart. OpenAPI/Swagger generated by FastAPI must match this contract.

## Global Rules

- IDs are opaque strings: `DS-*`, `PLAN-*`, `REQ-*`, `RUN-*`.
- Timestamps are RFC 3339 UTC strings; operational scheduling uses `Asia/Taipei`.
- Kilograms use JSON numbers and are rounded only for display; calculations retain controlled decimal precision.
- Distances are meters; durations are seconds; utilization is a ratio from `0` upward.
- Excel list strings are normalized to JSON arrays.
- Unknown request fields are rejected.
- Every response carries `X-Request-ID`; body includes `request_id` for errors and key mutations.
- Provider modes are `GOOGLE`, `TDX`, `SIMULATED`, `MIXED`, or `UNAVAILABLE` and must never be mislabeled.

## Error Envelope

```json
{
  "error": {
    "code": "TIME_WINDOW_CONFLICT",
    "message": "訂單無法在指定配送時段內完成。",
    "field_errors": [
      {
        "path": "orders[3].time_slot",
        "code": "TIME_WINDOW_CONFLICT",
        "message": "AM 路線預估超過 12:00。",
        "value_summary": "AM"
      }
    ],
    "request_id": "REQ-01J...",
    "details": {
      "affected_ids": ["ORD-004"],
      "retryable": false,
      "suggested_action": "調整時段或人工重新分配。"
```

Stable codes include `DATASET_VALIDATION_FAILED`, `MANUAL_REVIEW`, `UNASSIGNABLE`, `TIME_WINDOW_CONFLICT`, `PLAN_NOT_FOUND`, `PLAN_VERSION_CONFLICT`, `PLAN_NOT_CONFIRMABLE`, `PLAN_ALREADY_DISPATCHED`, `URGENT_ORDER_INVALID`, `URGENT_INSERT_UNASSIGNABLE`, `PROVIDER_UNAVAILABLE`, `AGENT_UNAVAILABLE`, and `LIMIT_REACHED`.

## Endpoints

### `GET /health`

Liveness only. `200`:

```json
{"status":"ok","service":"ai-delivery-dispatch-agent","request_id":"REQ-01J..."}
```

### `GET /ready`

`200` when API, database, and deterministic core are ready. Optional provider degradation does not make the app unready.

```json
{
  "status": "ready",
  "components": {
    "database": "ready",
    "optimizer": "ready",
    "openai": "degraded",
    "google_routes": "disabled",
    "tdx": "disabled"
  },
  "request_id": "REQ-01J..."
}
```

### `POST /api/v1/datasets/import-excel`

Multipart field: `file`; allowed `.xlsx`; size limit is configured. Import does not create a plan.

`201`:

```json
{
  "dataset_id": "DS-001",
  "status": "VALIDATED",
  "counts": {"orders":40,"packages":80,"vehicles":4,"zones":5},
  "total_weight_kg": 365.0,
  "validation": {"is_valid":true,"error_count":0,"warning_count":0},
  "request_id": "REQ-01J..."
}
```

If invalid, return `422 DATASET_VALIDATION_FAILED` with all safe field errors; the dataset metadata may remain queryable for audit.

### `GET /api/v1/datasets/{dataset_id}`

Returns metadata, normalized summary, counts, hash, import time, and validation status. It does not return the complete original workbook by default.

### `GET /api/v1/datasets/{dataset_id}/validation`

Returns validation summary and field errors/warnings.

### `POST /api/v1/plans`

Request:

```json
{
  "dataset_id": "DS-001",
  "route_provider_preference": "AUTO",
  "traffic_mode": "AUTO",
  "simulation_seed": 20260901
}
```

`AUTO` uses Google/TDX only when enabled/healthy; otherwise explicit simulated fallback. Response `201` is the Plan shape with `state=PROPOSED`. `409/422` may return a partial plan reference plus exceptions when no full feasible plan exists.

### `GET /api/v1/plans/{plan_id}`

Query `version` is optional; omitted means current version. Returns Plan or `404 PLAN_NOT_FOUND`.

### `POST /api/v1/plans/{plan_id}/confirm`

Request:

```json
{"version":2,"confirmation":"CONFIRM_PLAN","dispatcher_reference":"demo-dispatcher"}
```

Requires exact version and explicit action. Returns `200` with `state=CONFIRMED` and audit event ID. Invalid plan/validator failure returns `409 PLAN_NOT_CONFIRMABLE`.

### `POST /api/v1/plans/{plan_id}/dispatch`

Request:

```json
{"version":2,"confirmation":"MARK_DISPATCHED"}
```

Only `CONFIRMED` exact version transitions to `DISPATCHED`; returns audit event ID. This records state only and does not control a real fleet.

Never expose credential values or raw auth failures.

## Status Code Policy

| Status | Meaning |
|---:|---|
| 200/201 | successful query/create |
| 400 | malformed request or unsupported file |
| 404 | resource not found |
| 409 | state/version conflict or non-confirmable plan |
| 413 | workbook too large |
| 422 | schema/domain validation failure |
| 429 | Agent/provider budget or rate limit |
| 503 | optional capability unavailable without allowed fallback; readiness only for core outage |

## CORS

Parse `CORS_ALLOWED_ORIGINS` as an explicit origin list. Credentials are enabled only if needed. `*` is allowed only in an isolated test profile and must make `/ready` fail or warn outside that profile.
