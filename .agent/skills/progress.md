# 進度更新程序

唯一進度檔：`docs/progress.md`。不得另建 `TODO.md`、`NOW.md`、`DONE.md`。

## 何時呼叫

- **每輪工作結束前**（強制，不可略過）
- 使用者問「現在做到哪」
- 發現新工作需要記錄
- 一項工作完成、要切換到下一項

## 更新步驟

1. 讀 `docs/progress.md`。
2. 把剛完成的 `NOW` 移到 `DONE`，**附上證據**（改了哪些檔案、測試結果、實際輸出）。
3. 從 `TODO` 挑出下一項放進 `NOW`。**`NOW` 永遠只能有一項。**
4. 本輪新發現的工作加進 `TODO`，標註來源（誰要求的、為什麼）。
5. 真正卡住的放 `BLOCKED`，並寫明解除條件。
6. 需要使用者決定的放 `待確認`。

## 檔案格式

```markdown
# 進度

最後更新：YYYY-MM-DD

## NOW
<單一項目。正在做什麼、屬於哪個功能（F1–F6）、完成的判定標準。>

## TODO
| # | 工作 | 對應功能 | 前置條件 |
|---|---|---|---|

## BLOCKED
| 工作 | 卡在什麼 | 解除條件 |
|---|---|---|

## 待確認
| # | 問題 | 影響 |
|---|---|---|

## DONE
### YYYY-MM-DD
- <做了什麼> — 證據：<檔案／測試結果／實際輸出>
```

## 寫入規則

- **DONE 必須附證據。** 沒有實際執行過的測試不得寫入。寫「測試通過」必須附上實際輸出的數字。
- **NOW 只能有一項。** 想同時做兩件事表示 `NOW` 定義得太大，拆開。
- **TODO 要標來源。** 半個月後要能回答「這項為什麼在清單裡」。
- 不刪 `DONE`，只往下累積。過長時把舊日期收進 `## DONE（歷史）` 分隔，不刪除。
- 不得把未完成的工作寫進 `DONE`，也不得為了讓清單好看而改寫歷史。

## 與其他文件的關係

- 產品規格變更 → 改 `spec-driven/ACTIVE_SPEC.md`，不是改這裡。
- 這裡只記錄「做到哪」，不記錄「要做什麼樣的功能」。
